# 核心概念

## 并发、并行、分布式

- **并发**：多个任务在同一时间段内**交替**执行，使得它们看起来像是同时运行的。
- **并行**：多个任务在同一时刻**真正同时运行**，通常依赖多个处理核心或多个计算资源。
- **分布式**：将任务拆分到**多台物理机器**上，通过**网络通信**协调完成共同目标。

> [!CAUTION]
>
> 所有并行和分布式程序都是**并发**的

### 并行两种方案

- **数据并行**：将待解决的问题所需要处理的**数据**分配给各个核，每个核在分配到的数据集上执行大致相似的操作。
- **任务并行**：将待解决的问题所需要执行的**各个任务**分配到各个核上执行。

### 协作 (coordination)

并行程序中，多个核之间需要协调工作，协调过程主要分为以下3种：

- 通信
- 负载均衡
- 同步



## 分布式内存系统、共享式内存系统

- **分布式内存系统 (distributed-memory system)**：每个处理器拥有自己的**局部内存**，彼此之间不能直接访问对方的内存，需要通过**网络连接**，通过**消息传递**的方式交换数据。不同处理器的内存彼此独立，不共享同一地址空间。
- **共享式内存系统 (shared-memory system)**：多个处理器**共享同一个地址空间**中的内存数据，每个处理器都可以访问这块共享内存。

### 共享式内存系统

共享式内存系统包括两类：

- **一致存储访问系统 (UMA)**：所有处理器访问任何一块内存的速度和带宽都一致。
- **非一致存储访问系统 (NUMA)**：每个处理器都有离自己比较近的本地内存，访问速度较快；但访问其他处理器的内存，速度就比较慢。





## 进程、线程、多任务

### 基本概念

- **进程 (process)**：应用程序运行时的一个实例，是计算机系统**资源分配**的基本单位。
- **线程 (thread)**：进程中的一个执行单元，是**CPU调度**的基本单位。
- **多任务 (multitasking)**：操作系统提供对**同时运行多个程序**的支持，使得多个任务看起来像是同时执行。

### 进程与线程的对比

1. 进程是计算机系统**资源分配**的基本单位。拥有**独立的地址空间和系统资源**。
2. 线程是**CPU调度**的基本单位。同一个进程内的每一个线程**共享地址空间、代码段等大部分资源**，但每个线程拥有自己**独立的程序计数器（PC）、寄存器和栈**。
3. 一个进程崩溃不会影响其他进程的运行，但是一个线程崩溃可能就导致整个进程终止。

### 为什么线程被称为“轻量级”的执行单元？

相较于完整的进程，线程的**创建、管理、切换的开销更小**；同时同一个进程中的线程之间**共享进程的大部分资源**，因此线程之间的协作通常更高效。

具体而言：

1. **共享资源**。同一个进程中的线程共享地址空间、代码段等大部分资源，无需为每个线程单独分配完整的地址空间和系统资源。
2. **创建开销小**。由于创建线程只需分配少量资源。因此创建线程会比创建进程更快。
3. **上下文切换开销小**。只需保存**寄存器、程序计数器、栈**等信息，不需要切换整个地址空间，因此切换的速度快于进程。
4. **线程间通信效率更高**。线程之间共享地址空间，可直接访问共享内存进行通信。无需像进程间通信那样通过管道、消息队列、共享内存等机制进行，更加高效。



## Cache

### Cache修改

当CPU向Cache写数据时，Cache中的值和主存中的值存在不一致。

解决方法：

- **写直达 (Write Throught)**：当CPU修改Cache中的数据之后，**立刻**把这个数据的整个Cache Line写入主存。
- **写回 (Write back)**：当CPU修改Cache中的数据后，在Cache中**标记这个Cache Line是脏的**（dirty bit），当这个Cache Line换出Cache时才写进主存；如果不是脏的，则换出Cache时不会写进主存。

### Cache一致性问题

在多核系统中，各个核的Cache存有相同变量的副本，当一个处理器更新Cache中该变量的副本时，**其他处理器应该知道该变量已经更新**，即其他处理器中Cache的副本也应该更新。这称为Cache一致性问题。

解决方法：

- 监听Cache一致性协议
- 基于目录的Cache一致性协议

#### 监听Cache一致性协议

想法来自于总线：每个 Cache **监听共享的总线**，监控其他处理器的读写操作，来更新自己 Cache 中的数据副本。

> 例如：
>
> CPU1 写了变量 X，会在总线上广播 "我写了 X"
>
> CPU2 和 CPU3 听到后，就知道自己缓存的 X 无效了，要重新加载

缺点：在大型网络上，广播是非常昂贵的

#### 基于目录的Cache一致性协议

系统中设置一个目录，记录每个 Cache Line 当前被哪些处理器缓存。当某处理器需要写一个变量的值时，可以**查询目录**，并且将含有该变量的 Cache Line 置为**非法（invalid）**。

> 例如：
>
> CPU1 想写变量 X，先告诉目录：“我要写 X”
>
> 目录查到 X 还被 CPU2 缓存着，就通知CPU2 作废它的副本
>
> 然后 CPU1 就可以安全写入

### 伪共享

主要发生在**共享内存**系统中。

具体发生情况：当多个核心访问**同一个 Cache Line** 中的**不同变量**时，即使它们操作的变量不同，也会因为共用同一个 Cache Line 而**频繁触发 Cache 一致性机制**，导致**性能急剧下降**。

> [!CAUTION]
>
> 伪共享不会引发错误结果，只是引发了不必要的访存，导致程序性能下降。

例如：

```c
/* Private variables */
int i, j, iter_count;

/* Shared variables initialized by one core */
int m = 8, n = 100, core_count = 2;
double y[8];

iter_count = m/core_count; // iter_count=4, 每个核心处理 4 个元素

/* Core 0 does this */
for (int i=0; i<iter_count; i++) {
    for (int j=0; j<n; j++) {
        y[i] += f(i,j);
    }
}

/* Core 1 does this */
for (int i=iter_count; i<2*iter_count; i++) {
    for (int j=0; j<n; j++) {
        y[i] += f(i,j);
    }
}
```

假设该共享内存系统有2个核，Cache Line是64bytes的，`sizeof(double)=8`.

那么一个Cache Line刚好能够存储8个`double`类型的数。

由于`y[0]`~`y[7]`在内存中是连续存储的，并且恰好占满了一个Cache Line

所以当两个核心同时执行`y[i]+=f(i,j)`时，会同时修改落在同一个Cache Line 不同位置的数据，系统为了保持 Cache 一致性，会频繁触发缓存同步，导致性能急剧下降。 

#### 优化方法

方法1：按照Cache Line填充padding，使得**每个Cache Line只放一个数据**。

```c
#define CACHE_LINE 64

typedef struct {
    double value;
    char padding[CACHE_LINE - sizeof(double)];
} padded_double;

padded_double y[8];
```



方法2：按核心分配局部数组，最后合并

```c
double y_private[core_count][8] = {0};// 存放局部结果

/* Core 0 */
for (i = 0; i < iter_count; i++) {
    for (j = 0; j < n; j++) {
        y_private[0][i] += f(i, j);
    }
}

/* Core 1 */
for (i = iter_count; i < 2 * iter_count; i++) {
    for (j = 0; j < n; j++) {
        y_private[1][i] += f(i, j);
    }
}

/* 最后合并 */
for (int c = 0; c < core_count; c++) {
    for (i = 0; i < m; i++) {
        y[i] += y_private[c][i];
    }
}
```



方法3：使用局部临时变量，减少写`y[i]`的次数

```c
/* core 0 */
for (i = 0; i < iter_count; i++) {
    double sum = y[i];

    for (j = 0; j < n; j++) {
        sum += f(i, j);
    }

    y[i] = sum; // 改成先用寄存器/局部变量累加，最后只写一次 y[i]
}

/* core 1 也是同理 
		...
*/
```



## 并行硬件分类

使用**Flynn分类法**对计算机体系结构进行分类.

|                                          | SD（Single Data, 单数据流） | MD（Multiple Data, 多数据流） |
| ---------------------------------------- | --------------------------- | ----------------------------- |
| **SI**（Single Instruction, 单指令流）   | SISD                        | SIMD                          |
| **MI**（Multiple Instruction, 多指令流） | MISD                        | MIMD                          |

### SISD(Single Instruction Single Data)

> 单指令流，单数据流

例如：冯诺伊曼架构，串行计算

### SIMD(Single Instruction Multiple Data)

> 单指令流，多数据流

SIMD 系统通过对多个数据执行相同的指令从而实现在多个数据流上的操作。

SIMD 计算机可以分成**向量计算机**和**阵列计算机**。

特点：

- SIMD 适合**数据并行**

- 所有ALU执行相同指令，**同步**工作，要么一起工作，要么一起空闲。

例如：

- CPU 向量指令集：一条向量指令同时处理多个数据元素

- **向量处理机**（如 Cray-1）：一条向量指令完成整个向量运算

- GPU中的单个**warp**：对不同数据流执行同一指令

> [!CAUTION]
>
> 注意：
>
> **GPU 整体**从 Flynn 分类角度更接近 **MIMD**，因为多个 SM 可以独立调度不同的 Warp、执行不同的指令流；而每个 SM 内部则采用 SIMT 执行模型，底层由 **SIMD** 风格的执行单元**同时执行一个 Warp 中多个线程的相同指令**。

### MIMD(Multiple Instruction Multiple Data)

> 多指令流，多数据流

MIMD 系统支持多个指令流在多个数据流上进行操作，通常包括一组完全独立的处理单元。

MIMD 系统有两种主要的类型，分别是 **共享内存系统**（主要用于核数较少的情况，主要是**线程**） 和 **分布式内存系统****（主要用于核数较多的情况，主要是**进程**） 。

特点：

- 异步执行（与SIMD不同）

例如：

- **GPU整体**：多个 SM 可独立调度不同 Warp、执行不同 Kernel 或不同指令流，因此GPU整体属于 MIMD
- **现代多核 CPU**（如 Intel Core、AMD Ryzen、Apple M 系列）：每个 CPU 核心可独立执行不同指令流，处理不同数据。
- **MPI 集群**：例如 100 台服务器，每台运行不同进程，处理不同数据。
- **超级计算机**：由成千上万个节点组成，每个节点独立执行程序并通过 MPI 通信。

### MISD(Multiple Instruction Single Data)

> 多指令流，单数据流

少见

### 总结

| 分类 | 指令流(I) | 数据流(D) | 特点                 | 典型代表                      |
| ---- | --------- | --------- | -------------------- | ----------------------------- |
| SISD | 单        | 单        | 串行计算             | 单核 CPU                      |
| SIMD | 单        | 多        | 一条指令处理多个数据 | SSE、AVX、GPU中的warp（SIMT） |
| MISD | 多        | 单        | 多种算法处理同一数据 | 容错系统、TMR                 |
| MIMD | 多        | 多        | 多核并行计算         | 多核 CPU、服务器              |



## 并行软件

### SPMD(Single Program, Multiple Data)

> 单程序，多数据流

SPMD不是在每个核上运行不同的代码。相反，SPMD程序**仅包含一段代码**，通过使用**条件分支**，可以让这一段代码在执行时表现得像是在不同处理器上执行不同的程序。

特点：

- SPMD可以实现**数据并行**和**任务并行**

例如：

1. 实现**任务并行**

```c
if (I'm thread/process 0)
	do this;
else /* I'm thread/process 1 */
	do that;
```

2. 实现**数据并行**

```c
if (I'm thread/process 0)
	operate on the first half of the array;
else /* I'm thread/process 1 */
	operate on the second half of the array;
```



> SIMD vs SPMD
>
> 不同点：
>
> - SIMD是硬件模型，SPMD是程序模型。
> - SIMD 通常跑在单核，SPMD通常跑在多核。
> - SIMD是指令级别并行模型，SPMD是程序级别的并行。
> - SIMD需要所有ALU跑同一条指令，而SPMD不需要同步，每个核异步执行
>
> 相同点：
>
> - 都是可以处理**多个数据流**

### 临界区

一次只能被**一个**线程或者进程执行的**代码块**（通常需要访问共享变量），需要线程或者进程**互斥地访问**该代码块

### 竞争条件

多个进程或者线程同时访问一个共享数据，并且该**共享数据的值与进程访问顺序有关**。

### 实现互斥的方法

- 互斥锁
- 忙等待
- 信号量

### 线程安全

如果一段代码可以**被多个线程同时执行**而**不引发错误或不一致的结果**，则这段代码就是线程安全的。



## 阿姆达尔定律

除非一个串行程序的执行几乎全部都并行化，否则，不论有多少可以利用的核，通过**并行化所产生的加速比**都会是**受限**的。



## 可扩展性

> **可扩展性**:
>
> 可扩展性描述一个并行程序在增加处理器数量时，性能能否持续提升的能力。

- **强可扩展性**：如果在增加进程/线程的个数时，**固定问题规模不变**，可以维持固定的效率，那么程序称为强可扩展的。
- **弱可扩展性**：如果在增加进程/线程的个数时，只有**以相同的倍率增加问题的规模**，才能使效率值保持不变，那么程序称为弱可扩展的。
